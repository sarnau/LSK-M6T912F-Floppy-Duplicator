LSK M6T912F — Autoloader

The mechanical disk changer that feeds the duplicator: input hopper, a motorised arm into the master drive, and accept / reject bins. A self-contained embedded device with its own microcontroller and firmware, driven by the duplicator over a serial link.

Sources: GT ground truth (wire + terminal) · FW proven from the duplicator disassembly · HW chip datasheets / board. The autoloader's own firmware was not dumped — its internals are described from the outside. See the main analysis.

A

Hardware

ChipRoleDatasheet
Microchip PIC16C578-bit MCU — the autoloader's brain: sequences the hopper/arm/bin motors, reads the position/jam sensors, and runs the serial command interpreter. 28-pin, 20 I/O, 2K×12 EPROM, 72 B RAM, DC–20 MHz. HWdatasheets/controller/PIC16C57.PDF
SGS-Thomson ST93C06256-bit (16×16 / 32×8) Microwire serial EEPROM — non-volatile store for the autoloader's lifetime cycle count (reported by V) and any calibration/config. 1 M write cycles, 5 V. HWdatasheets/controller/ST93C06.PDF

The PIC's 20 I/O lines are enough to drive the three motor paths (hopper feed, drive arm, accept/reject diversion) and read the sensor set the status byte reports (hopper-seated, hopper-empty, disk-in-drive, reject-bin, accept-output). The ST93C06's 256 bits (32 bytes) comfortably hold the 32-bit counter plus a few calibration bytes. HW · inferred

B

Serial protocol

  • RS-232, 9600 baud, 8N1 GT.
  • On the duplicator it is Z80 SIO channel A, ports 0xD0 (data) / 0xD4 (control) FW. The host-PC remote link is the other SIO channel, B, at 0xD8/0xDC.
  • One ASCII byte per command; the autoloader answers with a single ASCII status character (and, for S/O/V, extra ASCII text). GT

S keeps returning the same status until a C resets it (GT). The duplicator's presence probe sends R while idle: an autoloader with nothing to eject still answers, so a reply means "connected" and a pure timeout means "not connected" (0x0220 → 0x024D) FW.

The command wrapper (al_cmd_ack 0x13D9) transmits the byte and tests the reply against 'X': equal → ok, timeout → code 1, anything else → code 2 FW.

C

Status codes & decode

S returns the status as two ASCII hex characters (e.g. "0B"), decoded at 0x13FB into one byte FW. Layout: a fault class in the high nibble and disk-presence bits in the low nibble — bit 1 = seated qualifier (bit 1 = 0 ⇒ "hopper not seated"), bit 3 (0x08) = disk in drive.

D

Counters & cross-reference

Two independent cycle counters

  • Autoloader's own count — a 32-bit total kept in the ST93C06 EEPROM, read only by the V command. This ROM never issues V, so the duplicator never reads it.
  • Duplicator's count — a separate 32-bit counter in the duplicator's CAT24C02 EEPROM (offset 0xFC, RAM cycle_cnt 0x3269/0x326B), bumped once per successful I/insert and shown by show_model_cycles. This is the number the duplicator's menus display.

Duplicator-side handlers live in the firmware analysis, §8 (Serial & protocols): the client command/ACK loop (0x13D9), the status decode (0x1286), the connection probe (0x0220). The link's electrical side (Z80 SIO + TC232 line driver) is in the README Serial / RS-232 connections.
